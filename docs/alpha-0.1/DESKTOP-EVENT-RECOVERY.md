# Desktop event recovery

The native desktop now reads durable journal history through `events.read`, a bounded, read-only method on the existing daemon IPC endpoint. The app's existing restricted credential has the required event-read permission; no approval, file-write or session-grant authority is added.

Each call scans at most 128 records and returns at most 512 KiB of visible event JSON. Invisible records advance the cursor without falsely reporting history loss. The head and record batch come from the same journal read transaction. Store replacement, daemon restart and an impossible future cursor explicitly restart replay; a real retention gap is reported separately. Restart replay also prevents a restored backup from silently reusing an old position.

The app reads at most four pages per refresh and stores one atomic cache at `app/history/events.json`: cursor and projected entries together, at most 1 MiB, 2,000 entries globally and 50 per download. Only event names, states, job ids and timestamps are retained. Original event payloads, addresses, file paths, approval details and session material are not copied. Unknown event kinds and ephemeral progress are omitted. Failed reads/writes keep the previous checkpoint; corrupt caches are rebuilt from the journal. The job inspector explains reconnecting, replaying, bounded history and retention loss.

The current job list remains a periodically refreshed snapshot. Requests are serialized, failed responses cannot replace it with an empty list, and a native list exceeding its 10,000-row collection bound returns an explicit failure. Event replay is descriptive and never rolls a newer snapshot back to an old state. This does not claim an atomic job-list snapshot across multiple pages, continuous push delivery, or preservation of every ephemeral progress sample. A failed initial connection still needs the daemon before current jobs can be loaded.

Validation: four daemon replay tests, 20 native app tests (including four cache cases), 90 API unit tests and eight IPC tests pass, with strict Clippy. Rust 1.90 all-target checks pass for the CLI and native app. The frontend passes 58 tests, typecheck and desktop/harness builds; the specification validator passes 261 examples.

The acceptance script `apps/client/tests/acceptance/s17-history-recovery.mjs` passes 16 checks against actual native binaries and a loopback 32 MiB file fixture in a fresh profile, including a frontend outage, missed pause/resume transitions, slow reads, webview reload, daemon restart and a corrupted display cache. The completed download matches the fixture SHA-256. Evidence and exact binary hashes: `D:/zeus-alpha/evidence/history/20261028-213054/`. The first UI attempt exposed a test-server path-normalization bug on Windows; normalizing the asset root fixed it. Installed release and Linux acceptance remain separate gates.
