# Sitemap discovery

The workflow runtime executes finite XML `urlset` and `sitemapindex` sources. Bootstrap requests use XML Accept headers and do not apply listing pagination. Discovered pages use the existing pagination/date-window implementation and approved extraction plan. `loc_pattern` filters page locations while nested indexes remain discoverable.

The parser refuses DTDs, unknown entities, missing/duplicate location fields, mixed core namespaces, malformed XML, credential-bearing URLs, fragments, off-host/port locations and HTTPS downgrades. It preserves signed query bytes after XML entity decoding. Standard sitemap namespaces and the legacy unqualified form are supported. Bounds are 8 MiB per document, 10,000 rows per sitemap, 100,000 elements and 32 XML levels. The daemon also decodes `.xml.gz` sources with an 8 MiB expansion cap, verifies all gzip members/checksums, rejects trailing junk and requires strict UTF-8. XML/HTML Accept choices propagate through both dry-run sampling and execution. Authenticated browser rendering remains separate work.

Nested discovery uses the plan's depth budget. A private checkpoint retains the expanded frontier, source ownership and bootstrap depth; it deduplicates cycles and repeated listing chains. XML requests count against page/time budgets and produce no download jobs themselves. The expanded frontier commits atomically before advancing the bootstrap chain. A storage failure leaves the previous checkpoint intact. A parse/scope failure pauses discovery without admitting a partial frontier.
