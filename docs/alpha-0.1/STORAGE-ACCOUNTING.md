# Scoped storage accounting

The native index records optional filesystem allocation and file identity alongside each file's logical length. The metadata and accounting queries use one retained, no-follow file handle beneath an enabled root. Unsupported allocation is unknown; it is never estimated from logical length.

The Storage view keeps its existing logical folder/type totals and adds an aggregate over the current included roots. Multiple indexed names with the same volume/file identity count once for observed allocation and unique logical size. Equal-size duplicate candidates exclude already observed aliases; content verification still reopens and hashes distinct objects. Link counts can reveal additional names outside the indexed selection, but Zeus does not inspect those paths.

Measurements describe the last indexed observation, not an atomic filesystem snapshot. Conflicting observations for an identity are excluded from known allocation and reported. Revoked roots are excluded at query time. Shared extents, filesystem deduplication and reflinks are not deduplicated; these values do not predict free space reclaimed by deletion. Parent directory logical totals overlap. Directory metadata, alternate streams and unrelated filesystem overhead are not a whole-volume usage inventory.

On Windows, allocation comes from `FileCompressionInfo` through `GetFileInformationByHandleEx`; link count and identity are read from the held handle. On Unix, allocated bytes use checked multiplication of `st_blocks` by 512. Native filesystem failures leave the optional field absent. See [Microsoft's handle information API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex), [compression information](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_compression_info) and [Linux stat fields](https://man7.org/linux/man-pages/man3/stat.3type.html).

The disposable metadata cache advances to ZIX2. ZIX1 snapshots still load with unknown allocation until rescan; unknown future formats or corrupt/oversized observations are refused. Updates without a fresh storage observation clear previous facts. No authoritative file-operation receipt or user file is migrated.
