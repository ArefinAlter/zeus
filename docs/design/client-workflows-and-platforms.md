# Download and file workspace: workflow research and implementation map

Primary documentation reviewed 2026-10-20; implementation map updated 2026-10-21 for the parallel continuation. Product observations below are sourced; the Zeus designs and acceptance targets are our engineering proposals. This extends [the workspace design](download-workspace.md). It is not evidence that every competitor feature or OS is implemented. The separate `docs/research` corpus was left untouched.

## Workflow families

These cover download queues, package collectors, command-line/headless engines, peer-to-peer clients, metadata search, disk analysis, dual-pane managers, terminal managers, native desktop browsing and remote synchronization. They are representative families, not a claim to have audited every client.

## Shared frontend architecture

The executable [Tauri 2 client](../../apps/desktop/README.md) follows ADR 0009. Its independent Rust workspace owns the authenticated daemon connection and a dedicated restricted Agent/Gui token. Five typed bridge commands expose real downloads, URL preview/review/enqueue, workflow reports, default-root files and artifact facts. The bundled local webview receives redacted projections and receipts, with no credential/session material, arbitrary RPC, shell/filesystem/HTTP/opener plugin or approval-decision command. Its approval list follows agent requester visibility; decisions remain in the verified CLI.

The current desktop preserves selection by stable identifier, pages at most 100 records, filters only the loaded page and refreshes every two seconds while visible. Connection/capability freshness gates mutations and reconnect invalidates retained link reviews. Persistent columns/saved filters and a durable event reducer remain planned. That reducer must carry a snapshot revision and durable cursor; gaps require a fresh snapshot. Progress may coalesce, while terminal states, approvals and errors cannot.

Current desktop pages cover Downloads, Link inbox, Runs, Files, artifact facts and restricted Approvals. Queues, Storage analysis, Destinations and full Settings remain planned. Small screens use list → detail navigation, not a miniature desktop table. Selection mode exposes the count and applicable actions; controls explain why mixed-state selections cannot share an action. Search input never shares global destructive shortcuts.

A frontend control is enabled only when its backend capability is implemented and negotiated. Downloaded, verified, quarantined, available locally and retained in CAS are independent facts. For providers, distinguish local hashing from remote checksum/readback and remote size-only evidence.

## Scoped file index

Everything documents the value of metadata indexing and journal updates, but its exact internal search algorithm is not a public contract in the sources reviewed. The following is a proposed Zeus design, not an assertion about proprietary internals.

1. Index only human-configured roots and each service's authorized subroots. Read permission and index membership are separate from write authority. Revoking a root immediately removes its results from every query, including counts and cached pages.
2. Store stable volume/file identity, parent identity, original name, normalized search key, size, allocated bytes when known, mtime and root visibility. Reconstruct paths from parent links so a directory rename does not rewrite all descendants. Preserve original filesystem spelling; case-insensitive search must never change write-path comparisons.
3. Start with ordered name/extension/size/time indexes and a bounded trigram posting index for substring queries. Intersect the rarest postings, then verify the original predicate. For fewer than three search characters, use a limited prefix lookup or budgeted scan; never promise constant-time arbitrary substring search. Regex/content search is an explicit cancellable job.
4. Apply changes in a transaction with an index generation and journal cursor. Queries return generation-bound cursors; stale generations trigger restart rather than skipped/duplicated results. Show scanning, current, degraded and offline states.
5. On Windows, investigate an optional, narrowly privileged metadata helper using documented [USN enumeration/read APIs](https://learn.microsoft.com/en-us/windows/win32/fileio/walking-a-buffer-of-change-journal-records). It supplies records for permitted roots; it cannot open arbitrary file contents or act as the download daemon. Validate record lengths and journal identity. Journal reset/wrap invalidates the cursor and requires reconciliation. Portable enumeration remains the fallback.
6. On macOS, establish the watcher before the initial scan and reconcile coalesced/dropped [FSEvents](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html). Linux starts with scoped enumeration plus watcher-triggered reconciliation; notification overflow, offline/network volumes and permission loss mark the index stale. No notification mechanism is assumed lossless.
7. Logical bytes sum visible file lengths. Physical allocation deduplicates hard links by file identity and reports unknown values; sparse files, compression and clone sharing prevent naive “reclaimable bytes” promises.

Acceptance targets, not measured results: benchmark 100k and 1m synthetic names; report p50/p95 query latency, memory per entry, initial scan cost and incremental lag on HDD/SSD. Include rename storms, journal wrap, disconnected roots, permission changes, Unicode, case collisions, long paths, hard links and stale pagination. A target of p95 ≤50 ms for warm filename queries is provisional until measured.

| Android ARM64; x86-64 emulator | Native transfer adapter and document-provider roots; shared UI/domain types where useful. | No Android application exists yet. [User-initiated transfer jobs](https://developer.android.com/develop/background-work/background-tasks/uidt?authuser=90) require OS-specific scheduling/notifications; [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files?authuser=104) returns granted document URIs, not arbitrary desktop paths. | iPhone/iPad ARM64; simulator | App-scoped persistence, platform file selection and background transfer adapter. | No iOS application exists yet. | 32-bit ARM/x86, RISC-V and other CPUs | Evaluate only after native dependencies and performance budgets are established. | No support claim. Avoid CPU-specific flags such as `target-cpu=native` in distributed builds; benchmark portable hashing and optional acceleration separately. |

[Tauri mobile plugins](https://v2.tauri.app/develop/plugins/develop-mobile/) allow native integration but do not supply background transfer or scoped-storage semantics automatically. Shared frontend code does not imply shared execution guarantees. Device-to-desktop control requires a separately designed authenticated transport; the current local IPC daemon must not acquire an incidental public listener.

The [GitHub runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) documents the CPU-specific runners used in the expanded informational matrix. CI configuration is not evidence that those jobs ran. Store identities, OAuth registrations, signing keys and physical-device testing remain release inputs.

## Design work for the remaining blockers

The table now distinguishes implemented subsets from remaining design/acceptance work. Focused verification for the parallel pass is 116 daemon + 52 workflow tests and 321 extension tests; final totals, desktop GUI results and publication SHAs are pending. Implementation does not substitute for installed-platform or live-account acceptance.

| Work item | Design and recovery rules | Required acceptance |
|---|---|---|
| Handoff batching | Implemented at enqueue: same requester/origin/browser family/nonempty profile/private-window flag; at most 50 jobs. Replay reuses the offer's job, joins change revision/hash, deadlines stay fixed and stale review is refused. | Hermetic isolation/replay/limit/stale-review tests pass. Non-enqueue joining and real installed browser suspension/reconnect acceptance remain open; no generic package or queue scheduler is implied. |
| Approval leaving, amendment and renewal | Implemented S32 leaving recomputes membership/bytes/destinations and sanitized display facts in the cancellation transaction. The final member stores a cancellation record; revision exhaustion atomically rebinds survivors at revision 1 under a fresh ID and unchanged expiry. Withdrawal shares the decision gate. | Shrink/hash/events, last-member and overflow tests pass. Non-cancel need disappearance, other widening paths and workflow grant renewal remain open. Session-backed workflow execution is still capability-gated. |
| Narrowed host credential | Implemented Human/NativeHost ceiling: only `daemon.read` and `nm.relay`. Legacy migration keeps token/ID/verifier; handshake and policy independently clamp authority. Popup decisions use verified native channel/gesture evidence rather than general API permission. | New/legacy credential and broad-injected-identity tests pass; a native fixture still batches/replays offers and records popup evidence. Real parent/extension, browser restart and unsupported-platform acceptance remain open. |
| Segment scheduling/control algorithms | Separate durable commit units from request segments. A scheduler leases contiguous missing units within an epoch; controller output sets bounded concurrency/range size under global and per-host caps. Commit fencing remains unchanged. | Overlap prevention, shrinking concurrency, pause/cancel/late workers, retries, range rejection, validators changing, HDD seek pressure and crash recovery. Requires coordinated core changes and measured throughput. |
| Sandboxed conversion | Versioned converter manifest; input handles read-only, private staging output, no network, bounded CPU/memory/time/output. Broker validates output, hashes, checks collision and atomically publishes with lineage. No shell command strings. | Linux/Windows/macOS sandbox implementations, hostile input, decompression bombs, child-process escape, timeout, partial output, rename race and restart. Disabled on unsupported sandboxes. |
| Model organizer classification | Model proposes labels mapped to deterministic organizer rules. Default metadata only; content disclosure requires separate consent. Bound input count/tokens/spend, validate output, preserve uncertain/unclassified files. Preview and ordinary organizer approval remain mandatory. | Hostile names/content, invalid labels/paths, uncertain output, budget exhaustion, privacy rules, stale file identity and provider failure. |
| Artifact retention/deletion/materialization | Implemented RPC `artifacts.lifecycle.preview/apply` and CLI saved-preview/apply flow. Exact current record/plan binding, bounded expiry and retry checkpoints guard effects; record deletion/retention weakening needs terminal approval. Tombstones preserve user files/shared CAS; materialization creates a verified no-replace copy in a permitted root. | Tests cover forged approval flags, shared content/user files, stale plans, collisions, interrupted foreign destinations and retry binding. GC administration, lifecycle MCP actions, import/export/events, concurrent reader/GC and adversarial platform containment remain open. |
| Workflow report fields | Implemented report version 1: plan/hash and approval/grant links, timestamps, active elapsed time, pause reason, incompleteness, safe error and detailed counts. Discovery counters commit with checkpoints; API job counts exclude unadmitted intents. Flat compatibility fields remain; old checkpoints stay version 0 with unknown detailed counts. | Focused workflow/daemon regressions cover checkpoint/report compatibility and actual job projections. Advanced extraction, authenticated/session-backed runs, conversions and release migration acceptance remain open. |

Next implementation order: finish contract/CI and installed trust acceptance; integrate real scheduling/control algorithms; build the scoped metadata index and remaining artifact operations; complete desktop event/recovery/accessibility behavior and sandboxed converters/model classification; then add mobile native transfer/storage adapters and release acceptance. Work on native applications can overlap once their platform boundary is fixed. A scaffold or a screenshot cannot satisfy installed-client acceptance.
