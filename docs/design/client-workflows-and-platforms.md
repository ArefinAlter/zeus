# Download and file workspace: workflow research and implementation map

2026-10-20. Primary documentation reviewed on this date. Product observations below are sourced; the Zeus designs and acceptance targets are our engineering proposals. This extends [the workspace design](download-workspace.md). It is not evidence that every competitor feature or OS is implemented. The separate `docs/research` corpus was left untouched.

| [Finder organization](https://support.apple.com/en-ca/guide/mac-help/mchle9f0a1b2/27/mac/27) | Tags and saved searches can present files together without moving them. | Separate tags/saved views from physical organizer rules. | [File Explorer accessibility](https://support.microsoft.com/en-us/accessibility/windows/use-a-screen-reader-to-explore-and-navigate-file-explorer-in-windows) | Tabs and navigation/content panes need predictable keyboard focus and screen-reader traversal. | Desktop table must preserve selection through filtering/events, expose focus/selection semantically and provide keyboard equivalents for drag operations. These cover download queues, package collectors, command-line/headless engines, peer-to-peer clients, metadata search, disk analysis, dual-pane managers, terminal managers, native desktop browsing and remote synchronization. They are representative families, not a claim to have audited every client.

## Shared frontend architecture

Keep the existing Tauri 2 direction from ADR 0009. The Rust shell owns the authenticated daemon connection and a closed command registry. The webview receives redacted views and typed operation receipts; it does not receive the IPC credential or session material. Begin with jobs, workflow runs, file previews and artifacts already supported by the daemon. Do not expose a generic `invoke(method, params)` bridge.

Use stable identifiers for selection, row keys and inspectors. Persist columns and saved filters separately from scheduling. An event reducer holds a snapshot revision and durable cursor; a gap discards speculative state and requests a fresh snapshot. Progress can coalesce; terminal states, approvals and errors cannot. Mutations remain disabled during reconnect until a fresh capability/authority snapshot exists.

Desktop navigation: Downloads, Link inbox, Queues, Runs, Files, Storage, Approvals, Destinations, Settings. Small screens use list → detail navigation, not a miniature desktop table. Selection mode exposes the count and applicable actions; controls explain why mixed-state selections cannot share an action. Search input never shares global destructive shortcuts.

A frontend control is enabled only when its backend capability is implemented and negotiated. Downloaded, verified, quarantined, available locally and retained in CAS are independent facts. For providers, distinguish local hashing from remote checksum/readback and remote size-only evidence.

## Scoped file index

Everything documents the value of metadata indexing and journal updates, but its exact internal search algorithm is not a public contract in the sources reviewed. The following is a proposed Zeus design, not an assertion about proprietary internals.

1. Index only human-configured roots and each service's authorized subroots. Read permission and index membership are separate from write authority. Revoking a root immediately removes its results from every query, including counts and cached pages.
2. Store stable volume/file identity, parent identity, original name, normalized search key, size, allocated bytes when known, mtime and root visibility. Reconstruct paths from parent links so a directory rename does not rewrite all descendants. Preserve original filesystem spelling; case-insensitive search must never change write-path comparisons.
3. Start with ordered name/extension/size/time indexes and a bounded trigram posting index for substring queries. Intersect the rarest postings, then verify the original predicate. For fewer than three search characters, use a limited prefix lookup or budgeted scan; never promise constant-time arbitrary substring search. Regex/content search is an explicit cancellable job.
4. Apply changes in a transaction with an index generation and journal cursor. Queries return generation-bound cursors; stale generations trigger restart rather than skipped/duplicated results. Show scanning, current, degraded and offline states.
5. On Windows, investigate an optional, narrowly privileged metadata helper using documented [USN enumeration/read APIs](https://learn.microsoft.com/en-us/windows/win32/fileio/walking-a-buffer-of-change-journal-records). It supplies records for permitted roots; it cannot open arbitrary file contents or act as the download daemon. Validate record lengths and journal identity. Journal reset/wrap invalidates the cursor and requires reconciliation. Portable enumeration remains the fallback.
6. On macOS, establish the watcher before the initial scan and reconcile coalesced/dropped [FSEvents](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html). Linux starts with scoped enumeration plus watcher-triggered reconciliation; notification overflow, offline/network volumes and permission loss mark the index stale. No notification mechanism is assumed lossless.
7. Logical bytes sum visible file lengths. Physical allocation deduplicates hard links by file identity and reports unknown values; sparse files, compression and clone sharing prevent naive “reclaimable bytes” promises.

Acceptance targets, not measured results: benchmark 100k and 1m synthetic names; report p50/p95 query latency, memory per entry, initial scan cost and incremental lag on HDD/SSD. Include rename storms, journal wrap, disconnected roots, permission changes, Unicode, case collisions, long paths, hard links and stale pagination. A target of p95 ≤50 ms for warm filename queries is provisional until measured.

## Platform and CPU matrix

| Platform | Planned execution model | Evidence and unresolved work |
|---|---|---|
| Windows x86-64 | Existing daemon, CLI/TUI, MCP and native host; Tauri desktop next. | This continuation runs Rust tests through the installed Windows toolchain. Installer/browser/keyring acceptance remains separate. |
| Windows ARM64 | Native build, same API, audited platform-specific IPC and containment. | Added informational `windows-11-arm` CI target. No successful run or device acceptance claimed. Do not substitute x86 emulation evidence. |
| Linux x86-64 / ARM64 | User daemon, Unix IPC, browser native host, desktop shell. | Existing x86 CI plus new informational ARM64 target. Real desktops, keyrings, filesystems and browser installs need acceptance. WSL-hosted Windows tests are not Linux tests. |
| macOS Intel / Apple Silicon | Native per-user daemon and Tauri shell, explicit native-host identity checks. | Added distinct informational Intel and ARM64 jobs. Browser-parent attestation, keyring, notarization and packaged GUI remain unaccepted. |
| Android ARM64; x86-64 emulator | Native transfer adapter and document-provider roots; shared UI/domain types where useful. | No Android application exists yet. [User-initiated transfer jobs](https://developer.android.com/develop/background-work/background-tasks/uidt?authuser=90) require OS-specific scheduling/notifications; [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files?authuser=104) returns granted document URIs, not arbitrary desktop paths. Test reboot, permission revocation, metering, battery restrictions and process death. |
| iPhone/iPad ARM64; simulator | App-scoped persistence, platform file selection and background transfer adapter. | No iOS application exists yet. [Background URLSession](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background) requires persistent session identity and completion reconciliation; an always-running desktop daemon is not the mobile design. Test real-device suspension, cancellation, reboot, low storage and file-provider loss. |
| 32-bit ARM/x86, RISC-V and other CPUs | Evaluate only after native dependencies and performance budgets are established. | No support claim. Avoid CPU-specific flags such as `target-cpu=native` in distributed builds; benchmark portable hashing and optional acceleration separately. |

[Tauri mobile plugins](https://v2.tauri.app/develop/plugins/develop-mobile/) allow native integration but do not supply background transfer or scoped-storage semantics automatically. Shared frontend code does not imply shared execution guarantees. Device-to-desktop control requires a separately designed authenticated transport; the current local IPC daemon must not acquire an incidental public listener.

The [GitHub runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) documents the CPU-specific runners used in the expanded informational matrix. CI configuration is not evidence that those jobs ran. Store identities, OAuth registrations, signing keys and physical-device testing remain release inputs.

## Design work for the remaining blockers

These are concrete implementation proposals, still requiring contract/threat-model review. They do not mark the corresponding features complete.

| Work item | Design and recovery rules | Required acceptance |
|---|---|---|
| Handoff batching | Reuse consent batching keyed by requester credential, browser instance, origin and compatible destination policy. Bind each offer ID once; freeze a reviewed revision and start a new batch for later arrivals. Cancel/withdraw updates revision and covered jobs atomically. | One-offer replay, cross-origin separation, mixed browser instances, limit overflow, disconnect and stale-review races. Coordinate extension and daemon changes. |
| Approval leaving, amendment and renewal | Removing the last waiting job withdraws a pending request. Any membership/budget widening produces new facts/hash/revision and clears confirmation. Renewal creates a separate request for a new validity interval; it cannot extend an expired lease before a fresh human decision. | Last-job exit, simultaneous decision/cancel, batched once grants, denial backoff, expired run resume, crash during amendment and audit failure. |
| Narrowed host credential | Split native relay identity from interactive decision authority. Bind relay access to attested browser parent, extension ID and connection epoch. Allow only the native protocol methods needed by that role; no broad admin fallback. | Forged parent/extension, replayed binding, stolen token, browser restart, unsupported platform and migration from old credentials all fail closed. |
| Segment scheduling/control algorithms | Separate durable commit units from request segments. A scheduler leases contiguous missing units within an epoch; controller output sets bounded concurrency/range size under global and per-host caps. Commit fencing remains unchanged. | Overlap prevention, shrinking concurrency, pause/cancel/late workers, retries, range rejection, validators changing, HDD seek pressure and crash recovery. Requires coordinated core changes and measured throughput. |
| Sandboxed conversion | Versioned converter manifest; input handles read-only, private staging output, no network, bounded CPU/memory/time/output. Broker validates output, hashes, checks collision and atomically publishes with lineage. No shell command strings. | Linux/Windows/macOS sandbox implementations, hostile input, decompression bombs, child-process escape, timeout, partial output, rename race and restart. Disabled on unsupported sandboxes. |
| Model organizer classification | Model proposes labels mapped to deterministic organizer rules. Default metadata only; content disclosure requires separate consent. Bound input count/tokens/spend, validate output, preserve uncertain/unclassified files. Preview and ordinary organizer approval remain mandatory. | Hostile names/content, invalid labels/paths, uncertain output, budget exhaustion, privacy rules, stale file identity and provider failure. |
| Artifact retention/deletion/materialization | Plan exact record IDs and expected versions. Separate tombstones from CAS reclamation; pins, active runs, lineage and unsettled deliveries protect bytes. Materialize through confined no-overwrite staging plus hash verification. GC takes leases and preserves references atomically. | Shared blobs, hidden owners, simultaneous readers/GC, changed plans, restarts, low disk, corrupt blobs, symlink/reparse races, rollback and idempotent receipts. CLI/MCP reads and ingest now exist; these mutations do not. |
| Workflow report fields | Introduce a versioned report with plan/revision, created/started/updated times, active elapsed time, pause reason, incomplete flag and counts. Discovery counters commit with the checkpoint; job counts derive from durable engine state. Backfill unknown legacy counters as unknown, not invented zeros. | Restart without double counting, duplicate/filter/robots paths, canceled/quarantined jobs, pending outbox jobs, paused elapsed time, missing old fields and no URLs in errors. Existing flat fields need a documented compatibility transition. |

Implementation order: complete the contract and agent surface now; then identity/approval lifecycle and scheduler integration; then the scoped file index and artifact lifecycle; then desktop shell wiring and converters/model classification; finally mobile native adapters and release acceptance. Work on native applications can overlap once their platform boundary is fixed. A scaffold or a screenshot cannot satisfy installed-client acceptance.
